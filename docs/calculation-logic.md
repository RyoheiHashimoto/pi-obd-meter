# 算出ロジック・閾値一覧

メーター表示・インジケーター・自動制御に関わるすべての計算式と閾値をまとめる。

> **凡例**
>
> - **config** = `configs/config.json` で車種ごとに設定可能
> - **ハードコード** = ソースコードに直接記述。変更するにはビルドが必要
> - 🚗 = 車種によってチューニングが必要な可能性がある値

## 1. 瞬間燃費推定

**ファイル:** `cmd/pi-obd-meter/fuel.go`

### 物理定数（ハードコード・車種非依存）

| 定数 | 値 | 説明 |
|---|---|---|
| 理論空燃比 | 14.7 | ガソリン車共通 |
| ガソリン密度 | 750 g/L | 標準的なレギュラーガソリン |
| 空気密度 | 1.225 g/L | 標準大気 (15°C, 1atm) |
| 標準大気圧 | 101.3 kPa | Speed-Density法の正規化に使用 |

### 🚗 車種チューニング値

| パラメータ | 現在値 | 設定方法 | 備考 |
|---|---|---|---|
| エンジン排気量 | 1.3 L | **config** (`engine_displacement_l`) | 燃費推定の基本パラメータ |
| 燃料レート補正係数 | 1.3 | **config** (`fuel_rate_correction`) | 理論値と実燃費の乖離を補正（暖機増量・過渡補正等） |
| アイドル燃料消費量 | 0.6 × 排気量 L/h | **排気量から導出** (`idleFuelRateCoeff * displacementL`) | 1.3L→0.78, 2.0L→1.2 L/h |
| エンブレ負荷閾値 | 5.0% | **ハードコード** (`load < 5.0`) | 走行中の極低負荷を燃料カットと判定 |
| エンブレMAP閾値 | 30.0 kPa | **ハードコード** (`engineBrakeMAPKPa`) | MAPセンサーがある場合の強い負圧による判定 |
| 燃費表示最低速度 | 10.0 km/h | **ハードコード** (`minDisplaySpeedKm`) | これ以下ではノイジーなため非表示 |
| 燃費表示上限 | 99.9 km/L | **ハードコード** (`maxDisplayKmL`) | 表示桁数の制限 |

### 計算フロー（優先順位: MAF > MAP > 負荷×RPM）

```
┌─ MAFセンサーあり ──→  fuelRate = MAF(g/s) × 3600 / (14.7 × 750)  [L/h]
│
├─ MAPセンサーあり ──→  Speed-Density法:
│   (MAFなし)            ve = MAP / 101.3  (体積効率の近似)
│                        airFlow = ve × (RPM / 2) × 排気量L / 60  [L/s]
│                        fuelRate = airFlow × 1.225 × 3600 / (14.7 × 750)  [L/h]
│
├─ 上記なし ─────→  負荷×RPM×排気量から推定:
│                        airFlow = (RPM / 2) × (負荷% / 100) × 排気量L / 60  [L/s]
│                        fuelRate = airFlow × 1.225 × 3600 / (14.7 × 750)  [L/h]
│
├─ RPM < 100 or 負荷 < 0.1% → fuelRate = 0.6 × 排気量 L/h（アイドル最低値）
│
├─ 補正係数を適用 ──→  fuelRate *= fuel_rate_correction (デフォルト 1.3)
│
└─ 燃費 = 速度(km/h) / fuelRate(L/h)  [km/L]
```

### エンブレ判定

走行中（≥ 10 km/h）のエンブレ（燃料カット）を2段階で検出:

1. **MAP ベース（優先）**: `intakeMAP < 30.0 kPa` — スロットル閉で強い負圧 = エンブレ
2. **負荷ベース（フォールバック）**: `load < 5.0%` — MAP非対応車向け

### 表示判定

| 条件 | 表示 | 戻り値 |
|---|---|---|
| speed < 0.5 かつ rpm < 100 | エンジン停止 | (0, 0) |
| fuelRate < 0.01 | 燃料カット | (-1, rate) |
| speed ≥ 10 かつ MAP < 30 kPa | エンブレ (MAP検出) | (-1, rate) |
| speed ≥ 10 かつ load < 5% | エンブレ (負荷検出) | (-1, rate) |
| speed < 10 | 低速非表示 | (0, rate) |
| 正常 | 燃費表示 | (km/L, rate) |

### 瞬間燃費を画面に数値で出すときの仕様 (2026-10-02)

書いた時点 (2026-10-02) では、画面の ECO 欄の数字は平均燃費 (`avg_fuel_economy`) で、
瞬間燃費 (`fuel_economy`) は葉アイコンの色にしか使っていなかった。いまは瞬間燃費を
バキューム計の中に数字とアークで出している (下の「画面での出し方」)。

#### 使うフィールド (すべて `/api/realtime` に既にある)

| フィールド | 意味 | 単位 |
|---|---|---|
| `fuel_economy` | 瞬間燃費。実車 (CAN 直結) では `calcFuelEconomy` の戻り値 | km/L (0 と -1 は特別な意味) |
| `fuel_rate_lh` | 燃料流量 | L/h |
| `speed_kmh` | 車速 | km/h |

**サーバ側の変更は要らない。** 表示側で切り替えるだけで足りる。

#### 表示の切り替え

| `fuel_economy` | 状態 | 出すもの |
|---|---|---|
| > 0 | 走行中 | `fuel_economy` を **km/L** |
| 0 | 停車・低速 (< 10 km/h) | **`fuel_rate_lh` を L/h** |
| -1 | エンブレ判定 | **`--` (数値を出さない)**。アークは一番短い状態 (点線ひとつ分) まで縮める |

**停車中に 0 km/L や空欄を出さない。** アイドリングでも燃料は流れている
(2026-09-28 の実測で MAF 2.54 g/s、`rate_lh` 0.87 L/h)。km/L は停車中に
定義できない (ゼロ除算) ので、L/h に切り替えるのが正しい。同じ欄を流量に
切り替える例はシュコダの純正表示、トヨタの特許、自作機 (MPGuino、OBDuino)。
国内の純正は「--」(マツダは約 5 km/h 以下)、社外品は 0 を出して流量を別項目に
しているものが多い (2026-10-02 の調査)。

式そのものは正しい。`speed [km/h] ÷ rate [L/h] = km/L` で次元が合う。
上限 99.9 km/L (`maxDisplayKmL`) でのクリップも表示としては妥当。

#### 画面での出し方 (2026-10-02 実装)

バキューム計の中 (以前の VACUUM ラベルの位置) に出す。`web/static/js/indicators.js` の
`updateInstantEco`。

- 届いた値をそのまま出さず、**直近2秒の距離と燃料をそれぞれ合計してから割る**。
  エンブレ判定 (-1) の間の値は合計に入れない
- **数字は1秒ごとに書き換える** (色は毎回)。2秒平均を小数2桁で出すと、2026-09-17〜28 の走行ログ
  約20時間で 0.4秒ごとなら 1秒に 2.4回、1秒ごとなら 0.9回数字が変わる
- 小数2桁 (平均燃費・バキュームの数字とそろえる)。km/L の上限は 99.99
- 内側のリングに「燃料の食い方」のアーク (走行は 1 − km/L ÷ 30、停車・低速は L/h ÷ 3)。
  エンブレ中は一番短い状態まで縮める (2026-10-08)。詳細は `docs/meter-indicators.md`

#### エンブレ (-1) のときの表示

**数字は `--`、アークは一番短い状態 (点線ひとつ分) まで縮めて残す (2026-10-08)。**
アークは「燃料の食い方」を表す (長いほど食っている) ので、燃料を切っている間は
最短が正しい。市販の燃費計 (テクトム 99.9 km/L、ScanGauge 9999 MPG) が燃費の上限に
張り付けるのと同じことを、逆向きの目盛りで表している。数字は実際の値ではないので
出さない。1300 rpm 未満の惰性 (`fuel_economy = -1` だが燃料は戻っている、`fuel.go`) も
同じく最短にする。

2026-10-04 に一度「燃料カット中はアークを右端に張り付ける (燃費が良いほど伸びる)」
形で入れたが、10-08 に、外側のバキュームと先端がそろって動く縮む形に変えた。

**「この判定は約半分が外れる」は誤りだった (2026-10-04 訂正)。** 当初、2026-09-28 の
走行でカット判定 (`MAP < 30` かつ `rpm >= 1300`) に当てはまる 85.0 分を燃料系状態
(PID 0x03) と照合し、49.5% (42.1 分) が `fsys=2` (クローズドループ) だったことから
「実際には燃料を噴いている」と書いた。しかし比べた `fsys` の値が古かった。

- 燃料系状態は補助 PID の巡回 (`can_loop.go` の `auxPIDs`、10 個を 5 秒で 1 周) に
  入っており、**約 5 秒に 1 回しか更新されない**。2026-09-17〜28 の走行ログで、
  値が変わる間隔は最短 4.86 秒、同じ巡回の短期燃料トリムは中央値 5.08 秒
- カット判定が続く長さは**中央値 2.6 秒** (1 秒以上続いた 2621 回)。短いカットの間は、
  カット前の古い「2」が残って見える
- 判定が長く続き、`fsys` が一度は更新された後だけを見ると、ほぼ当たっている。
  10 秒以上続いた 197 回の 5.5 秒以降は **92.3%** が `fsys=4` (開ループ = カット側)、
  20 秒以上続いた 40 回の 10.5 秒以降は **97.7%**
- 全区間をそのまま数えると 53.7% (4) / 46.2% (2) で、9/28 の 49.5% と同じ見かけになる

残りの 2〜8% が本当の誤判定か、更新の遅れの残りかは、この粒度では分からない。
`fsys` の値「4」は全開時の燃料増量でも出るので、それだけでカットとも言えない。

**実車では表示用と積算用の判定は食い違わない (2026-10-02 訂正)。** 当初
「表示用はスロットル、積算用は MAP で判定が違う」と書いたが、誤りだった。
スロットルで判定する `calcDisplayFuelEco` が呼ばれるのは `ev.IsFull` が
偽のとき、つまり ELM327 の `ReadFast` 経路だけ。CAN 直結では
`isFull := true` が固定で入る (`can_loop.go:676`、「CAN直結では全データが
常時取得可能なため常にIsFull」)。実車は can0 直結なので、`fuel_economy` には
積算と同じ `calcFuelEconomy` の結果がそのまま入る。

```
CAN 直結 (実車)   → IsFull=true  → calcFuelEconomy     (MAP < 30)
ELM327 の ReadFast → IsFull=false → calcDisplayFuelEco  (throttle)
```

**判定を `fsys` に変える案は、今の読み方では成り立たない (2026-10-04 訂正)。**
当初「`fsys` に変えれば精度は上がる」と書き、2026-09-29 に全区間で試して
1 区間は改善 (-4.8% → -1.8%)、別の区間は悪化 (+6.5% → +8.3%) した。しかし
`fsys` は約 5 秒遅れの値で、中央値 2.6 秒のカットには追いつかない。この試算の
結果は、判定の良し悪しより更新の遅れを映している可能性が高い。`fsys` を判定に
使うなら、まず専用の枠で読んで更新を速くする必要がある (その分 MAF・MAP の
読み取りが減る)。

補正係数 1.12 の見直しは「判定が約半分外れている」ことを前提に待っていたが、
その前提は上のとおり崩れた。見直しの進め方は、前提を外して考え直す必要がある。

## 2. 速度ゲージ

**ファイル:** `web/static/js/gauge.js`

### アーク構成

- 角度: 270°アーク（-135° → +135°、7時半～4時半の位置）
- 🚗 最大値: **config** (`max_speed_kmh`, デフォルト 180)

| スナップ閾値 | 0.05 | これ以下で目標値に即収束 |
| 停止閾値 | 0.01 | これ以下でアニメーション停止 |

|---|---|---|
| ≥ 120 km/h | 赤 | `#f44336` |
| ≥ 100 km/h | 橙 | `#ff9800` |
| ≥ 80 km/h | 黄 | `#ffeb3b` |
| ≥ 60 km/h | 薄緑 | `#69f0ae` |

> 法定速度に基づくが、車種・用途によって閾値を変えたい場合がある。

## 3. スロットルアーク

**ファイル:** `web/static/js/gauge.js`

速度ゲージの内側に重ねて表示。スロットル開度を視覚化する。

### 🚗 アイドル開度ベースライン

**config** (`throttle_idle_pct`, デフォルト 11.5)

> **車種依存度: 高。** ECU によってアイドル時の報告値が異なる。
> DYデミオは 11-12% 程度だが、車種によって 5-20% まで幅がある。
> config.json で車種ごとに設定可能。

生のスロットル値からベースラインを引いてゼロ始まりに正規化:

```
表示% = max(0, (生OBD値% − idle) / (max − idle) × 100)
```

### 色（ハードコード・車種非依存）

HSL色相が開度に応じて連続変化:

```
色相 = 210° × (1 − 開度% / 100)
```

| 開度 | 色相 | 色 |
|---|---|---|
| 0% | 210° | 青（巡航） |
| 50% | 105° | 緑 |
| 100% | 0° | 赤（全開） |

### 補間（ハードコード）

LERP係数 = 0.4（速度ゲージの 0.35 より速い追従）

## 7.1 航続距離 (RNG)

**ファイル:** `internal/fuel/estimate.go`, `cmd/pi-obd-meter/fuel.go` (`calcRangeToEmpty`)

```
RNG = 推定残量 (L) × 平均燃費 (km/L, 給油間)
```

推定残量は燃料計 (0x430 B0) をそのまま使わず、次のように作る。

| 処理 | 内容 |
|---|---|
| 毎周期 | 使った燃料 (燃料レート × dt、燃料カット中は 0) を引く |
| 毎周期 | 燃料計の値へ時定数 10分で寄せる (走行中・停車中とも) |
| 起動時に1回 | 最初に落ち着いた値と 4.5L (= 10pt) 以上離れていたら、その値に合わせる (給油) |
| 保存 | 30秒かつ 0.05L 以上変わったら `fuel_estimate.json` へ。再起動したら保存値から続ける |

燃料計はスロッシングで大きく振れ、停車直後は航続距離換算で 10〜25km、30秒
止まっても 3〜6km 動く (2026-09-07/08 の実走ログ、停車38回)。以前の実装は
停車中だけ直近1秒の平均を取り直していたため、停車のたびに RNG が跳ね、
走行中は減らなかった。燃料計を5分平均すれば ±0.5〜0.7pt に収まるので、
長い時定数で寄せれば揺れは表示に出ない。

エンジンをかけたまま給油した場合は起動を経ないため、燃料計への寄せで
10〜30分かけて追いつく。

### 精度の確認 (2026-10-08)

**満タンから燃料計 30pt あたりまで、推定残量のずれは ±1.8L 以内で、減るにつれて
広がる傾向は無い。** 航続距離にすると約 ±20km (12km/L 換算)。平均燃費の誤差
(区間積算の累積 -2.2%) を合わせても ±20〜25km 程度。燃料計の帯ごとの換算表は
作らなくてよい (改善がこの揺れに埋もれる)。

**確かめ方。** 推定残量は長い目で見ると「燃料計 × 0.45」に寄る。補正係数を直した
後 (8/31 以降) の満タン〜満タンの 5 区間で、それと実際の残量を比べた。

- 実際に使った燃料 = drive ログの燃料積算 (`rate_lh` × dt、5 秒以内の刻みだけ) ×
  (レシート ÷ その区間の積算)。区間の積算は `internal/fuel/refuel.go` の区間の表と一致
- 燃料計は 5 分ごとの中央値で読む (スロッシュを均す)。上端の頭打ち (93pt 以上) は除く
- 区間の境は、燃料計がファイル間で 10pt 以上跳ねた所 (給油)。同じ起動の
  `drive-XXXX.csv` (先頭のスナップショット) と `drive-XXXX-1.csv` (本体) は、この順に並べる。
  ファイル名の日付で区切ると、区間の途中に給油が入って結果が壊れる (一度やった)

## 10. メンテナンスリマインダー

**ファイル:** `internal/maintenance/manager.go`

詳細は [configuration.md](configuration.md) を参照。

### 計算式

**距離ベース:**

```
進捗 = (現在総走行距離 − 最終リセット時距離) / 間隔km
警告 = 進捗 ≥ 警告閾値
期限切れ = 進捗 ≥ 1.0
```

**日付ベース:**

```
進捗 = 経過日数 / 間隔日数
警告 = 進捗 ≥ 警告閾値
期限切れ = 進捗 ≥ 1.0
```

同日再通知なし（1日1回まで）。

## 11. トリップ積算

**ファイル:** `internal/trip/tracker.go`

### 計算式（車種非依存）

| 項目 | 計算式 |
|---|---|
| 距離 Δ | `(speedKmh / 3600) × Δt秒` を毎サイクル加算 |
| 燃料消費 Δ | `(fuelRateLH / 3600) × Δt秒`（fuelRateLH > 0 の場合のみ） |
| 平均燃費 | `距離km / 燃料消費L`（0.05L 未満は非表示） |
| 平均速度 | `距離km / 走行時間秒 × 3600` |
| 走行時間 | speed > 1.0 km/h の累積秒数 |
| アイドル時間 | speed ≤ 1.0 km/h の累積秒数 |

- 10秒超のギャップはデータ欠損とみなしスキップ
- 状態永続化: **0.1km (100m) 走行ごと**にアトミック書き込み（距離ベース保存）

## 13. OBD スパイク除去フィルター

**ファイル:** `cmd/pi-obd-meter/filter.go`

OBD値のノイズ（ELM327通信エラーによる異常値）を除去する。

### パラメータ（ハードコード）

| パラメータ | 値 | 説明 |
|---|---|---|
| 最大変化量 | 20 | 1サイクルで許容する最大変化量 |
| 最大リジェクト回数 | 3 | 連続リジェクト後に値を強制受入 |

### ロジック

```
1. 前回値との差が最大変化量以内 → 受入
2. 差が最大変化量超 → リジェクト（前回値を維持）
3. 連続リジェクトが maxRejects 回に達したら → 強制受入（実際の急変に追従）
4. 正常値を受入した時点でリジェクトカウンタをリセット
```
