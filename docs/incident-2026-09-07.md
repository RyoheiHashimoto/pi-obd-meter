## 何が起きたか

メーターの TRIP が 0 になり、燃費表示が壊れ、時計が巻き戻り、過去の起動ログが消えた。
**症状は4つに見えたが、原因は1つ。`/data`（SSD）が消えていた。**

```
/data/pi-obd-meter/trip_state.json   → TRIP と燃料積算
/data/state/timesync                 → 時刻の永続化（RTC が無い）
/data/log/journal                    → journal の永続化
```

## 真因

**AIC8800 ドングルが、同じ USB ハブ上の SSD を叩き落としていた。**

```
[2.161] usb 1-1.3: ELECOM ESD-EXS 接続（ハブのポート3）→ 正常にマウント
[6.572] usb 1-1.1: ドングル切断  (a69c:5723 Aic MSC)
[7.297] usb 1-1.1: 再列挙        (a69c:8d80 AIC Wlan)
[7.612] usb 1-1.1: また切断      → aicwf_usb_disconnect enter
[8.321] usb 1-1.1: また再列挙    (368b:8d83 AIC 8800D80)
[9.014] AICWFDBG: aicwf_usb_rx_complete need to wait for disconnect callback
[9.574] usb 1-1.3: stat urb: status -71   ← 0.5秒後、SSDが壊れ始める
```

| | ドライバあり | ドライバなし |
|---|---|---|
| SSD が落ちるまで | 9.5 秒 | 落ちない |
| USB `-71` | 数百回 | **0 回** |
| `/data` | 消える | 維持 |

**皮肉なことに、このドングルは内蔵 WiFi が不安定だから追加したもので、`wlan1` すら
生成できていなかった。** 役に立たないまま SSD を殺していた。→ #183（撤去して close）

## 外れた仮説（同じ道を通らないために）

この障害と、並行して追った内蔵 WiFi の件で、**断定して外したのが 11 回。**

| 主張 | なぜ外れたか |
|---|---|
| ユーザーが SSD を抜いたせい | 挿しっぱなしだった |
| ケーブルか端子が死んだ | 起動時は正常に繋がっていた。動作中に落ちている |
| ポートを電源から入れ直したが駄目 | `disable` は論理的にポートを切るだけで VBUS は切れない。テストが成立していなかった |
| SSD はハブのポート1 | ポート3。`usb-storage 1-1.1` はドングルの MSC モードの誤読 |
| 2.4GHz 専用チップ | BCM4345/6 で両対応。`nmcli` の型番表示が誤り |
| CPU 負荷 | 累計値と1回分を比較した測定ミス |
| `set_channel fail` が原因 | 最初の失敗より**後**に始まる |
| BSSID 固定が失敗の原因 | 固定を解除した後も同じペースで失敗が継続 |
| 電波干渉（新発見だと報告） | 2026-08 に記録済み。しかも「消去法で飛びついた悪い例」として記録されていた |
| Mac 側が落ちた | 落ちていない |
| 撃ち直しを速くすれば繋がる | 20 回撃っても実際の試行は 12 回。supplicant のペースは変わらない |

**共通するのは「全体を読む前に1行で結論を出した」こと。** `dmesg` を最後まで読めば、
ドングルの件は最初の1回で分かった。

## 自分で作った害

| やったこと | 結果 |
|---|---|
| 接続の切断/再接続を短時間に繰り返す実験を2回 | 2回とも Pi をネットから失い、深夜にエンジン再始動を強いた |
| watchdog から復旧の段を外してから実験 | 戻す手段が無い状態を自分で作った |
| `Type=oneshot` を `multi-user.target.wants` に配置 | **起動を3分118msブロック**（`systemd-analyze blame` 1位） |
| `overlayroot-chroot` を短時間に連続実行 | 下層が **rw のまま残った**（電断で SD が壊れる状態） |
| 走行中に 30MB のデプロイ | 転送が途中で切れた |

**すべて「動いているものを止めない」「復旧経路を先に確保する」で防げた。**

## 対処と結果

```
ドングル       ドライバをブラックリスト化（下層へ永続化）+ 物理撤去
brcmfmac       debug=0x8400 を有効化 → WiFi の機序特定に唯一効いた
poll22         停止（ATF 同定は完了済み。ATF はアプリが自分で読む）
wifi-fast-connect  撤去（測定で効果なしと確認）
```

以後の起動で `-71` は 0 回、`/data` は維持。TRIP・燃料積算は無事だった
（アプリが `/data` の欠如を検知して縮退モードに入り、読み書きを止めていたため上書きされなかった）。
