# プロジェクト概要

30秒で全体像が分かるための要約。設計の詳細は `docs/architecture-overview.md`。

## 何か

**車載メーター + 走行記録システム。** 車の CAN バスを直接読み、速度・回転数・
スロットル・インマニ圧・瞬間燃費を 5インチ LCD にリアルタイム表示する。
走行距離とメンテナンス状態を Google Sheets に自動記録し、スマートフォンから
給油記録・ODO 補正・メンテナンス管理を行う。

**開発機はマツダ DYデミオ (DBA-DY3W / ZJ-VE 1.3L)。実車に搭載して日常的に稼働中。**

## 技術構成

```
ECU → CAN HAT (MCP2515/SPI) → Go 単一バイナリ → WPE WebKit (cog) → 5インチ LCD
                                    ↓
                           Google Apps Script → スプレッドシート
                                    ↕
                              スマートフォン
```

- **言語**: Go 1.25（ARM64 クロスコンパイル、単一バイナリ配布）
- **通信**: SocketCAN 直読み（主）／ ELM327 シリアル（フォールバック）
- **表示**: 素の JavaScript + SVG。WPE WebKit を labwc (Wayland) 上でキオスク起動
- **配信**: HTTP + WebSocket（ローカル完結）
- **記録**: Google Apps Script + スプレッドシート
- **CI/CD**: GitHub Actions（テスト → ARM64 ビルド → リリース）
- **配布**: systemd timer による OTA 自動更新

Web フレームワーク・フロントエンドフレームワークとも不使用。標準ライブラリで構成。

## 設計上の判断

### 制約から出発している

| 制約 | 設計 |
|---|---|
| 予告なく電源が落ちる（エンジン停止＝電断） | 状態ファイルは tmp + fsync + rename の原子的書き込み |
| SD カードの書き込み寿命 | swap 無効化、ログは RAM 上、状態保存は 0.1km 走行ごと |
| 走行中に再起動できない | OTA 更新は起動時に1回のみ実行 |
| メモリ 2GB | Chromium ではなく WPE WebKit、フレームワーク不使用 |
| ネットワークが不安定 | 送信失敗はキューに退避し指数バックオフで再送。表示系はローカル完結で影響を受けない |
| ECU 応答が律速 | CAN は問い合わせず流れているフレームを受信 |

### 依存の向きを一方向に保っている

ドメイン層（距離・燃費・メンテナンス判定）は `net/http` もシリアルも CAN も
import していない。結果として、**車もネットワークも SD カードも無い環境で
全テストが実行できる**。実装 5,829行に対しテスト 5,034行という比率はこの構造に依存している。

### 測定に基づいて撤回している

`revert` コミット 6件。例として、起動時の Wi-Fi 接続を速くする施策を実装したが、
実測の結果「待ち時間は自分側ではなく `wpa_supplicant` 側が決めている」と判明したため
撤去した（根拠が壊れた変更を残すと以後の測定の交絡になるため）。
調査記録は `docs/wifi-troubleshooting.md`。

## 運用

- **リリース**: develop → main の PR、CI 通過後にタグ、GitHub Actions が ARM64 バイナリを生成。
  6か月で 25 リリース（最新 v1.5.0）
- **配布**: 車両側が起動時に新バージョンを検出して自動更新（走行中には更新しない）
- **監視**: `/api/health` で OBD/ネットワーク接続・送信キュー長・稼働時間を公開
- **障害対応**: 起動時 Wi-Fi 接続失敗をドライバのデバッグ出力まで降りて切り分け。
  上流の未解決 issue と同一症状であることまで確認（`docs/wifi-status16-research.md`）
