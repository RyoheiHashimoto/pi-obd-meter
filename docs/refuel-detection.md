# 給油の自動検出

CAN の燃料残量 (0x430 B0) の跳躍から給油を検出する。給油ボタンを押さなくても
トリップがリセットされ、給油記録が残る。

## 仕組み

**給油中は Pi の電源が落ちている。** エンジンを切って給油するので、走行中の
監視では検出できない。「電源が落ちる前」と「次に立ち上がった後」を比較する。

```
停車中に残量を保存 → 電源断 (給油) → 次回起動 → 停車中の残量と比較
                                        → 10ポイント以上の跳躍なら給油
```

1. **停車中だけサンプルを採る** — 走行中はスロッシングで 24〜33 ポイント振れる
2. **直近20サンプルの平均**を「落ち着いた値」とする
3. 前回保存値との差が **10.0 ポイント以上**なら給油と判定
4. 判定は**起動につき1回だけ**

閾値の根拠は実測。32回の起動境界で、給油は +86.7 ポイント、それ以外の最大は
+3.5 ポイントだった。**25倍の開き**がある。

## 実装上の落とし穴 (すべて実際に踏んだ)

**基準値を累積平均にしてはいけない。** 走行中に燃料が減るため、起動後の全停車
サンプルの平均は実際の残量より高く出る。90pt で出発し 40pt で到着すると保存値は
約 65pt になり、満タン給油の跳躍が 55pt ではなく 30pt と算出される (45%過少)。
→ 直近20サンプルのリングバッファにした (#141)。

**毎サンプル保存してはいけない。** `Update` は 50ms 周期で呼ばれるため、
停車中の毎回保存するとアイドリング20分で約24,000回 SD に書く。
→ 30秒間隔かつ 0.5pt 以上の変化があるときだけ書く (#141)。

**イベントをメモリだけに持ってはいけない。** 起動直後は WiFi が繋がるまで
時間がかかり、実際に「WiFi接続待ちタイムアウト」で初回送信がスキップされた。
そのままエンジンを切れば記録は永久に失われる (保存値は既に給油後の値に
更新されているため、次回起動では跳躍が検出できない)。
→ 状態ファイルに保持し、送信成功まで持ち越す (#147)。

## 給油量は満タン時に出さない

燃料センダーは **raw 243 (95.3%) でクリップ**する。給油直後から11分間
95.29pt に張り付いたままで、燃料が減って測定範囲に戻ってから初めて 90.6pt に
なった。**満タン時の読みは「上限に達した」以上の情報を持たない。**

跳躍量から算出した 40.69L に対し、レシートは 35.29L。**15%過大**だった。

→ 満タン判定時は `AmountL` を出さない (#148)。跳躍量は較正の材料として残す。
記録の起点は量ではなく `refuel_detected` フラグにしてある。量を条件にすると
満タン給油が丸ごと記録されず、トリップのリセットまで失われるため。

## 運用

```
1. 給油する
2. エンジンをかけて発進前に20秒ほど停車
3. あとでレシートの給油量をダッシュボードから入力
```

**ボタンを押す前に行が1つ増えているのが正常。** 手動入力するとその行が
上書きされる (#140)。行は増えず、トリップも再リセットされない。
燃費と誤差% は手動入力したときに初めて計算される。

自動検出の役割は「給油があったことの検出」と「トリップのリセット」であり、
**給油量は推定にすぎない。** 燃費検証に使ってきた誤差% の列を汚さないため、
自動行では空欄にしてある。
