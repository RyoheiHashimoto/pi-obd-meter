# DY デミオ (ZJ-VE) の CAN / PID マップ

2026-08 の実走解析で判明したことの記録。**ここに書いていないものは分かっていない。**

対象: マツダ デミオ DY3W / ZJ-VE (1348cc) / FN4A-EL (Ford 4F27E) 4速AT

---

## 1. 診断通信の構造

**この車の診断バスに応答する ECU は PCM ひとつだけ。**

```
7DF  ブロードキャスト要求  → 7E8 (PCM) のみ応答
7E0  PCM 個別アドレス      → 7E8 応答
7E1  変速機 (一般的な割当) → 無応答
```

変速機は独立した ECU を持たず PCM が統合制御している。ATF 油温を探すとき
7E1 を叩いても何も返らない。**Mode 22 の要求は 7E0 に送ること。**

Mode 22 (拡張診断データ) の全 65,536 通りを走査した結果、**有効な PID は 87 個**。

---

## 2. ATF 油温 — 0x17B3

長らく「取得不可」としていたが、実機で同定した。

```
要求   7E0#03 22 17 B3 00 00 00 00
応答   7E8#05 62 17 B3 XX 00
換算   °F = raw × 42/25 − 57
       °C = raw × 0.93333 − 49.4444
分解能 1℃
```

ScanGauge の公式 X-Gauge 定義 `Mazda CANSF Transmission Temperature`
(TXD `07E02217B3` / MTH `002A0019FFC7` / 華氏) と一致する。

**当初 `°C = raw − 40` と誤って実装した。** 他の温度 PID からの類推で決めつけ、
検証しなかった。その式では首都高走行で 120℃ に達し、水温より 31℃ も高くなる。
実車の報告では高速走行中の油温は水温とほぼ同じで、辻褄が合わなかった。
正しい式では +1.3℃ となって実態と一致する。

### 同定の根拠

1. **同じ水温で発熱条件を正反対にすると差が出る**
   水温90℃で停車中 64℃ / 走行中 72℃。水温由来の値なら一致するはずで、
   実際 0x114D は +0.23℃ で一致してしまい派生値と判明した。
2. **熱容量がある** — 走行中は単調に増え、1〜2分の停車では下がらない。
   停車4分間の変動幅は 0.00℃。
3. **停車アイドル暖機で大きく遅れる** — 水温が 65→88℃ と 23℃ 上がる間に
   49.5→51.4℃ と 2℃ しか上がらない。トルコンが仕事をしない停車中は
   ラジエータの熱交換器だけで温まるため。
4. **カウンタではない** — 別の日には 49℃ を指していた。
5. **生値 (0x17BD) と対で存在する** — 下記。

### 0x17BD は同じセンサーの生値

`17B3` が 1 変わるごとに `17BD` が決まった値を返す (σ≒0)。別の日のデータも
同じ曲線に乗る。NTC サーミスタの生値と変換値の関係。

```
17B3 = 135 → 17BD = 53.0
17B3 = 155 → 17BD = 33.0
17B3 = 176 → 17BD = 20.0
```

ECU が温度センサーの生値と変換値を別々の PID で持つのは自然で、
`0x114D` (水温センサー生値) と `0x0105` (水温) も同じ構造になっている。

### この車には存在しない油温 PID

ScanGauge の一覧には `11BD` `1E1C` という別の油温 PID もあるが、
**DY デミオには存在しない** (全数走査で応答なし)。新しいマツダ車向け。

## 3. 同定できた PID

| PID | 正体 | 確度 |
|---|---|---|
| 0x17B3 | ATF 油温 (℃) | 確定 |
| 0x17BD | ATF 油温センサーの生値 | 確定 |
| 0x17B2 | ギア段のビットフィールド (1速=1 / 2速=2 / 3速=4 / 4速=8) | 確定 |
| 0x17BA | ロックアップ フラグ (0 / 65280 の二値) | 確定 |
| 0x114D | 水温センサーの生値 (NTC) | 確定 |
| 0x114A | 吸気温の派生値 | 確定 |
| 0x1717 | ロックアップ 3段階 (0=解放 / 1=部分 / 3=完全) | 有力 |
| 0x1678 | オープンループ (増量) フラグ | 有力 |
| 0x1631 | クローズドループ フラグ | 有力 |
| 0x17BE | 車速に比例 (車速×9.55、σ0.4%) | 有力 |
| 0x1169 | 走行中 / 停車中フラグ | 中 |

標準 PID (0x00xx / 0x01xx) は Mode 01 と同じ意味を持つ。とくに有用なもの:

| PID | 内容 | 備考 |
|---|---|---|
| 0x03 | 燃料システム状態 | 2=クローズドループ / 4=オープンループ(増量) |
| 0x06 / 0x07 | 短期 / 長期燃料トリム | (raw−128)×100/128 % |
| 0x0E | 点火時期 | raw/2 − 64 ° BTDC |
| 0x42 | ECU 電源電圧 | 充電制御の観測に使える |
| 0x1F | エンジン稼働時間 (秒) | 始動からの経過を確認できる |
| 0x3C | 触媒温度 | (raw)/10 − 40 ℃ |

**外気温センサーは無い。** 標準 PID 0x46 は非対応で、Mode 22 の 87 個にも
外気温らしい値は存在しなかった。走行中の吸気温 (0x0F) の最低値が代用になる
(実測で外気温 +10℃ 程度)。停車すると熱を吸って使えなくなる。

**大気圧センサーも無い。** 標準 PID 0x33 は非対応 (2026-08-31 に対応PID
ビットマップで確定)。エンジン油温 0x5C も非対応。

実害は無い。`calcFuelEconomy` は MAF を最優先で使い、実機でも MAF 経路が
動いている。MAF は空気の質量を直接測るので標高による空気密度の低下を自動で
織り込む。`atmosphericKPa = 101.3` のハードコードは、MAF を持たない車で
Speed-Density に落ちたときだけ効く。

### 2026-08-31 に新たに確認できた標準PID

| PID | 内容 | 実測値 |
|---|---|---|
| 0x43 | 絶対負荷 (Absolute Load Value) | アイドル 18.8% |
| 0x3C | 触媒温度 Bank1 Sensor1 | 518℃ |

`0x43` は SAE J1979 で大気圧補正済みと定義される正規化値。MAF を持たない
車の燃料モデルには MAP より適した入力になりうる。この車では MAF があるので
使っていない。

`0x3C` は触媒の過熱監視に使える。触媒過熱は実在する故障モードである。

## 4. 情報を持たない PID

**定数** (17個) — 走行しても値が変わらない。

```
0000 0013 001C 0020 0021 0030 0040 0200 0202
0968 1681 16F0 1706 1709 1718 1783 17A6
```

**他の量の派生** — 3走行の突き合わせで、単一の量だけで決まると判明。

```
車速から決まる     1631(部分的) 16CE
回転数から決まる   17B5 17B6 17B8 16CF 1177 1153 002C
吸気圧から決まる   0900 1173
```

`0x17Bx` が固まっているので変速機の油圧やソレノイドを期待したが、
**17B5 / 17B6 / 17B8 はギアに依存せず回転数だけで決まる**ため油圧ではない。

## 6. 同定の手順 — 2回間違えた教訓

温度らしい値を見つけても、それが「独立した温度」か「他の温度から導かれた値」
かを必ず切り分けること。**2回続けて誤った。**

```
0x114A → 吸気温の派生値だった (ATF油温と誤認)
0x114D → 水温センサーの生値だった (ATF油温と誤認)
```

### 効かない判定

**相関の高さ** — 0x114D と水温の相関は -0.996 だったが派生値だった。
車の温度はどれも一緒に上がるので、独立した温度どうしでも相関は高く出る。

**ラグ** — 「熱容量があれば応答が遅れる」という理屈でラグを見たが、暖機中の
データはどちらも滑らかな単調曲線なので、どのラグでも相関が 0.94〜0.997 と高く、
ピークが平坦で判定にならなかった。0x114D のピークは lag −20秒 で r=−0.9969、
lag 0 でも −0.9959 と差が 0.001 しかない。

### 効く判定

**同じ基準温度で、条件を正反対にして比べる。**

派生値なら「基準の温度が同じなら値も同じ」になる。独立した温度なら発熱条件が
違えば値も違う。ATF なら停車アイドルと高速走行でトルコンの発熱が桁違いなので、
水温が同じでも油温は大きく変わる。

**注意: ログ全体の最高速で分類してはいけない。** サンプルごとの瞬間車速で
分けること。87℃のサンプルが走行前のアイドリング中だったなら、条件を変えた
比較になっていない。最初これを間違えた。

```
0x114D  水温87℃のとき 停車中 37.49 / 走行中 37.38  → 一致 = 派生値
0x17B3  水温90℃のとき 停車中 64℃  / 走行中 72℃    → 差あり = 独立
```

**日をまたいだ一貫性** も強力。条件の違う複数の走行で同じ関係が成り立つかを
見る。単一の走行では、たまたま相関しているだけの量を拾ってしまう。

## 7. CAN ブロードキャスト (Mode 22 ではない)

`internal/can/frame.go` を参照。要点のみ:

| ID | 内容 |
|---|---|
| 0x201 | B0-1 RPM (raw/4) / B4-5 車速 / B6 スロットル (200=全開) |
| 0x230 | B0 ギア / **B2 機械ギア比 ×100** (滑りは含まない) |
| 0x231 | B0 ギア+レンジ / B1 bit7=HOLD bit4=ロックアップ bit3=変速中 |
| 0x420 | B0 水温 (raw−40) / B1 距離パルス (8bit ローリング) |
| 0x430 | B0 燃料残量 / B4-5 オドメーター (raw×10 km) |
| 0x4B0 | 4輪速度 |

**0x230 B2 はトルコンの滑りを含まない。** 実効ギア比と誤解して実装し、
ロック率が常に 100% になる不具合を出した (#132)。滑りは rpm と車速から
物理的に求めること。

**0x231 のロックアップフラグは「完全締結」しか示さない。** フラグが OFF でも
実際の滑りは 2〜10% で、完全解放ではなくスリップ制御であることが多い。
実測では 4速「解放」の 80% が滑り 1.10 未満だった。

### 公式資料由来の TC 制御仕様

`docs/can-gear-ratio-analysis.md` に記録されている、ニューモデル速報の記述。
**実測で観測した現象の説明になる。**

```
減速スリップ L/U 制御
  減速時にスリップ制御を併用して燃料カットゾーンを拡大する。
  エンジン回転をタービンより高く維持し、燃料カットを長く保つ。
```

→ 実測で**惰行中の滑り比が 1.0 未満になるサンプルが 21.9%** あった理由。
エンジンがタービンより遅く回る (滑り<1) のではなく、**意図的に高く保っている。**

```
ロックアップ条件
  3速: 約 36 km/h までロックアップ
  4速: 約 800 rpm に落ちるまでロックアップ、その後 23 km/h まで減速スリップ制御
```

```
0x210 は全 195万フレームで B0-B1 = 0xFFFF 固定。
タービン回転数は CAN に出ていない (ECU 内部でのみ使用)。
```

→ Mode 22 の `0x17B0` を「タービン回転数では」と疑ったが、ロックアップ中でも
エンジン回転との比が 0.85 で 1.000 にならず否定された。**そもそも出ていない。**

### 未確認

- **R レンジのギア比** — 理論値 2.648 なら B2=9 のはずだが、実測は 26 (1速と同じ)。
  低速バック入庫のデータしかなく未確認。R で TC ロック時のデータが要る。
