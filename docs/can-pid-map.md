# DY デミオ (ZJ-VE) の CAN / PID マップ

2026-08 の実走解析で判明したことの記録。**ここに書いていないものは分かっていない。**

対象: マツダ デミオ DY3W / ZJ-VE (1348cc) / FN4A-EL (Ford 4F27E) 4速AT

---

## 1. 診断通信の構造

**この車の診断バスに応答する ECU は PCM ひとつだけ。**

```
7DF  ブロードキャスト要求  → 7E8 (PCM) のみ応答
7E0  PCM 個別アドレス      → 7E8 応答
7E1  変速機 (一般的な割当) → 無応答
```

変速機は独立した ECU を持たず PCM が統合制御している。ATF 油温を探すとき
7E1 を叩いても何も返らない。**Mode 22 の要求は 7E0 に送ること。**

Mode 22 (拡張診断データ) の全 65,536 通りを走査した結果、**有効な PID は 87 個**。

---

## 2. ATF 油温 — 0x17B3

長らく「取得不可」としていたが、実機で同定した。

```
要求   7E0#03 22 17 B3 00 00 00 00
応答   7E8#05 62 17 B3 XX 00
換算   °F = raw × 42/25 − 57
       °C = raw × 0.93333 − 49.4444
分解能 1℃
```

ScanGauge の公式 X-Gauge 定義 `Mazda CANSF Transmission Temperature`
(TXD `07E02217B3` / MTH `002A0019FFC7` / 華氏) と一致する。

**当初 `°C = raw − 40` と誤って実装した。** 他の温度 PID からの類推で決めつけ、
検証しなかった。その式では首都高走行で 120℃ に達し、水温より 31℃ も高くなる。
実車の報告では高速走行中の油温は水温とほぼ同じで、辻褄が合わなかった。
正しい式では +1.3℃ となって実態と一致する。

### 同定の根拠

1. **同じ水温で発熱条件を正反対にすると差が出る**
   水温90℃で停車中 64℃ / 走行中 72℃。水温由来の値なら一致するはずで、
   実際 0x114D は +0.23℃ で一致してしまい派生値と判明した。
2. **熱容量がある** — 走行中は単調に増え、1〜2分の停車では下がらない。
   停車4分間の変動幅は 0.00℃。
3. **停車アイドル暖機で大きく遅れる** — 水温が 65→88℃ と 23℃ 上がる間に
   49.5→51.4℃ と 2℃ しか上がらない。トルコンが仕事をしない停車中は
   ラジエータの熱交換器だけで温まるため。
4. **カウンタではない** — 別の日には 49℃ を指していた。
5. **生値 (0x17BD) と対で存在する** — 下記。

### 0x17BD は同じセンサーの生値

`17B3` が 1 変わるごとに `17BD` が決まった値を返す (σ≒0)。別の日のデータも
同じ曲線に乗る。NTC サーミスタの生値と変換値の関係。

```
17B3 = 135 → 17BD = 53.0
17B3 = 155 → 17BD = 33.0
17B3 = 176 → 17BD = 20.0
```

ECU が温度センサーの生値と変換値を別々の PID で持つのは自然で、
`0x114D` (水温センサー生値) と `0x0105` (水温) も同じ構造になっている。

### この車には存在しない油温 PID

ScanGauge の一覧には `11BD` `1E1C` という別の油温 PID もあるが、
**DY デミオには存在しない** (全数走査で応答なし)。新しいマツダ車向け。

標準 PID (0x00xx / 0x01xx) は Mode 01 と同じ意味を持つ。とくに有用なもの:

| PID | 内容 | 備考 |
|---|---|---|
| 0x03 | 燃料システム状態 | 2=クローズドループ / 4=オープンループ(増量) |
| 0x06 / 0x07 | 短期 / 長期燃料トリム | (raw−128)×100/128 % |
| 0x0E | 点火時期 | raw/2 − 64 ° BTDC |
| 0x42 | ECU 電源電圧 | 充電制御の観測に使える |
| 0x1F | エンジン稼働時間 (秒) | 始動からの経過を確認できる |
| 0x3C | 触媒温度 | (raw)/10 − 40 ℃ |

**外気温センサーは無い。** 標準 PID 0x46 は非対応で、Mode 22 の 87 個にも
外気温らしい値は存在しなかった。走行中の吸気温 (0x0F) の最低値が代用になる
(実測で外気温 +10℃ 程度)。停車すると熱を吸って使えなくなる。

**大気圧センサーも無い。** 標準 PID 0x33 は非対応 (2026-08-31 に対応PID
ビットマップで確定)。エンジン油温 0x5C も非対応。

実害は無い。`calcFuelEconomy` は MAF を最優先で使い、実機でも MAF 経路が
動いている。MAF は空気の質量を直接測るので標高による空気密度の低下を自動で
織り込む。`atmosphericKPa = 101.3` のハードコードは、MAF を持たない車で
Speed-Density に落ちたときだけ効く。

### 2026-08-31 に新たに確認できた標準PID

| PID | 内容 | 実測値 |
|---|---|---|
| 0x43 | 絶対負荷 (Absolute Load Value) | アイドル 18.8% |
| 0x3C | 触媒温度 Bank1 Sensor1 | 518℃ |

`0x43` は SAE J1979 で大気圧補正済みと定義される正規化値。MAF を持たない
車の燃料モデルには MAP より適した入力になりうる。この車では MAF があるので
使っていない。

`0x3C` は触媒の過熱監視に使える。触媒過熱は実在する故障モードである。

## 4. 情報を持たない PID

**定数** (17個) — 走行しても値が変わらない。

```
0000 0013 001C 0020 0021 0030 0040 0200 0202
0968 1681 16F0 1706 1709 1718 1783 17A6
```

**他の量の派生** — 3走行の突き合わせで、単一の量だけで決まると判明。

```
車速から決まる     1631(部分的) 16CE
回転数から決まる   17B5 17B6 17B8 16CF 1177 1153 002C
吸気圧から決まる   0900 1173
```

`0x17Bx` が固まっているので変速機の油圧やソレノイドを期待したが、
**17B5 / 17B6 / 17B8 はギアに依存せず回転数だけで決まる**ため油圧ではない。

## 6. 同定の手順 — 2回間違えた教訓

温度らしい値を見つけても、それが「独立した温度」か「他の温度から導かれた値」
かを必ず切り分けること。**2回続けて誤った。**

```
0x114A → 吸気温の派生値だった (ATF油温と誤認)
0x114D → 水温センサーの生値だった (ATF油温と誤認)
```

### 効かない判定

**相関の高さ** — 0x114D と水温の相関は -0.996 だったが派生値だった。
車の温度はどれも一緒に上がるので、独立した温度どうしでも相関は高く出る。

**ラグ** — 「熱容量があれば応答が遅れる」という理屈でラグを見たが、暖機中の
データはどちらも滑らかな単調曲線なので、どのラグでも相関が 0.94〜0.997 と高く、
ピークが平坦で判定にならなかった。0x114D のピークは lag −20秒 で r=−0.9969、
lag 0 でも −0.9959 と差が 0.001 しかない。

### 効く判定

**同じ基準温度で、条件を正反対にして比べる。**

派生値なら「基準の温度が同じなら値も同じ」になる。独立した温度なら発熱条件が
違えば値も違う。ATF なら停車アイドルと高速走行でトルコンの発熱が桁違いなので、
水温が同じでも油温は大きく変わる。

**注意: ログ全体の最高速で分類してはいけない。** サンプルごとの瞬間車速で
分けること。87℃のサンプルが走行前のアイドリング中だったなら、条件を変えた
比較になっていない。最初これを間違えた。

```
0x114D  水温87℃のとき 停車中 37.49 / 走行中 37.38  → 一致 = 派生値
0x17B3  水温90℃のとき 停車中 64℃  / 走行中 72℃    → 差あり = 独立
```

**日をまたいだ一貫性** も強力。条件の違う複数の走行で同じ関係が成り立つかを
見る。単一の走行では、たまたま相関しているだけの量を拾ってしまう。

## 7. CAN ブロードキャスト (Mode 22 ではない)

`internal/can/frame.go` を参照。要点のみ:

| ID | 内容 |
|---|---|
| 0x201 | B0-1 RPM (raw/4) / B4-5 車速 / B6 スロットル (200=全開) |
| 0x230 | B0 ギア / **B2 機械ギア比 ×100** (滑りは含まない) |
| 0x231 | B0 ギア+レンジ / B1 bit7=HOLD bit4=ロックアップ bit3=変速中 |
| 0x420 | B0 水温 (raw−40) / B1 距離パルス (8bit ローリング) |
| 0x430 | B0 燃料残量 / B4-5 オドメーター (raw×10 km) |
| 0x4B0 | 4輪速度 |

**0x230 B2 はトルコンの滑りを含まない。** 実効ギア比と誤解して実装し、
ロック率が常に 100% になる不具合を出した (#132)。滑りは rpm と車速から
物理的に求めること。

**0x231 のロックアップフラグは「完全締結」しか示さない。** フラグが OFF でも
実際の滑りは 2〜10% で、完全解放ではなくスリップ制御であることが多い。
実測では 4速「解放」の 80% が滑り 1.10 未満だった。

### 公式資料由来の TC 制御仕様

`docs/can-gear-ratio-analysis.md` に記録されている、ニューモデル速報の記述。
**実測で観測した現象の説明になる。**

```
減速スリップ L/U 制御
  減速時にスリップ制御を併用して燃料カットゾーンを拡大する。
  エンジン回転をタービンより高く維持し、燃料カットを長く保つ。
```

→ 実測で**惰行中の滑り比が 1.0 未満になるサンプルが 21.9%** あった理由。
エンジンがタービンより遅く回る (滑り<1) のではなく、**意図的に高く保っている。**

```
ロックアップ条件
  3速: 約 36 km/h までロックアップ
  4速: 約 800 rpm に落ちるまでロックアップ、その後 23 km/h まで減速スリップ制御
```

```
0x210 は全 195万フレームで B0-B1 = 0xFFFF 固定。
タービン回転数は CAN に出ていない (ECU 内部でのみ使用)。
```

→ Mode 22 の `0x17B0` を「タービン回転数では」と疑ったが、ロックアップ中でも
エンジン回転との比が 0.85 で 1.000 にならず否定された。**そもそも出ていない。**

### 未確認

- **R レンジのギア比** — 理論値 2.648 なら B2=9 のはずだが、実測は 26 (1速と同じ)。
  低速バック入庫のデータしかなく未確認。R で TC ロック時のデータが要る。

## 2026-09-01 に同定した Mode 22 PID

### 0x1101 — ステータスビット (ブレーキ / ラジエータファン)

| ビット | 意味 | 確度 |
|---|---|---|
| bit0 | ラジエータファン | 確定 |
| bit1 | ブレーキペダル | 確定 |
| bit3 | 走行中ほぼ常時1 (未同定) | — |
| bit7 | 稀に1 (未同定) | — |

**bit1 = ブレーキ。** 停車・アイドル・アクセル全閉で固定した状態で、20秒踏む → 離す →
20秒踏む、を実施した。95個の全 PID のうち、この操作に一致した唯一の PID だった。

```
00:32:10 - 00:32:26  b1=2  (1回目の20秒)
00:32:32 - 00:32:53  b1=0  (離した)
00:32:57 - 00:33:18  b1=2  (2回目の20秒)
00:33:21 - 00:33:31  b1=0
押した区間14サンプル全部2 / 離した区間8サンプル全部0
```

過去ログでも裏が取れた。2026-08-28 20:04 の急減速 (-5.69 m/s²、3日間で唯一 5 を超えた)
では、bit1 が立った瞬間から速度が崩れている。

```
20:03:59  bit1=0  76 km/h
20:04:02  bit1=1  67 km/h  ← 踏んだ
20:04:05  bit1=1  29 km/h
```

**bit0 = ラジエータファン。** サイドブレーキを疑って試験したが、引いている最中に 0 に
なる矛盾が出た。水温と突き合わせると答えが出た。

```
bit0=0 のとき  水温 95→98℃ と上昇
bit0=1 に      水温 97→89℃ へ下降
bit0=0 に戻る  また 90℃ へ
```

**サイドブレーキは CAN に出ていない。** ブロードキャストも 70 秒間まったく反応せず、
Mode 22 にも該当なし。機械式ワイヤーで警告灯の switch がメーターへ行くだけなので、
PCM が知る必要がない。一方フットブレーキは**ロックアップ解除に必須**なので PCM が持つ。

### 0x3201 — 勾配 (負 = 登り)

符号付き16bit。**大橋JCT (高低差71m、勾配8.9%、2周の螺旋) の登坂で特定した。**

```
車速48-60km/h・定常(|a|<0.3) で揃えた比較
  大橋ループ  n=13  中央 -690
  他の区間    n=55  中央    0
```

決め手は3つ。

**1. 加速度と無相関** (r=+0.009)。加速度センサーの写しではない。

**2. 登坂中だけ連続して負になる。** 0.85km 連続。74km の走行中、-500 未満は20件しか
なく、**うち15件 (75%) がこの2km区間に集中**していた。

**3. 登り切った瞬間に符号が反転する。**

```
km 28.22-28.50   -80 〜 +510    進入
km 28.56-29.41   -240 〜 -1010  ★登坂中ずっと負
km 29.46-29.50   +990, +1320    ★登り切って正に反転
km 29.60         +20            平常
```

単なる負荷やトルクの写しなら反転しない。

**当初の候補 098E / 1746 は外れだった。** 平地データで「停車中は固定・走行中に動く・
車速と無相関」という条件で17個から2個に絞ったが、実際の8.9%登坂では動かなかった。
098E はむしろ登坂中に**下がった** (0 vs 12)。平地データからの絞り込みには限界がある。

### 副産物 — GPS 無しで経路を復元できた

2026-09-01 の首都高一周 (79.57km) で、GPS 測位ゼロのまま経路を復元できた。

- **距離**: パルス計数 (0x420 B1) と公表の路線キロ程を突き合わせる
- **勾配**: 燃料レートが同速度比で 2.0 倍 → 8.9% 登坂と一致
- **JCT**: 低速・低ギア・S+HOLD の持続時間で識別 (大橋の螺旋は 85 秒)

推定した経路は運転者の申告と一致した。**ただし入口 IC の特定まではできていない** (距離
だけでは ±1km の誤差が残り、C1 と 6号向島線の区間長を概算で置いたため)。

### 燃料からの標高推定 (副産物)

平坦な往復走行で熱効率を較正すると、燃料の熱量と走行抵抗の差から標高差が出せる。

較正: 新東名 214km で 17.7%、首都高一周 75km で 18.9% → η=18% を採用。
どちらも往復なので勾配が相殺し、較正に使える。

| 区間 | 距離 | 推定標高差 | 平均勾配 | 備考 |
|---|---|---|---|---|
| 新東名 上り | 214 km | +198 m | +0.1% | 検算。ほぼ平坦で妥当 |
| 首都高 一周 | 75 km | −139 m | −0.2% | 検算。一周なのでほぼゼロ |
| **比叡山 登坂** | 14.1 km | **+832 m** | **+5.9%** | 実際の山頂 848m と整合 |
| 比叡山 下り | 10.4 km | +100 m | +1.0% | **失敗** |

**下りでは使えない。** 降坂中は燃料カットが効いて燃料をほとんど使わず、仕事をするのは
重力なので、燃料の熱量から逆算する前提が崩れる。登坂専用の手法である。

短い急坂も苦手で、大橋JCT (実際 +71m) は +19m と出た。窓に登坂以外の区間が混ざる
ことと、低負荷域では η=18% の仮定が粗くなるため。**数km以上の持続した登坂でのみ使える。**

## 0x1103 / 0x1104 — エアコンコンプレッサー (2026-09-01 同定)

| PID | ビット | 意味 |
|---|---|---|
| 0x1103 | bit2 | エアコンコンプレッサー |
| 0x1104 | bit0 | 同上 (冗長系か、要求と実際の別) |

**走行済みのログだけで同定できた。** 夜間走行中にエアコンを入れたり切ったりしていたため、
アイドル停車中の入切が記録に残っていた。

判別にはアイドル時の MAP を使う。コンプレッサーが噛むと吸気圧が上がる。

    アイドル中 (車速0・600-1100rpm) の MAP は二峰性
      30-31 kPa … コンプレッサー OFF
      43-46 kPa … コンプレッサー ON

この状態で全 PID を突き合わせた結果:

| | ON | OFF |
|---|---|---|
| n | 6,033 | 5,203 |
| MAP | 44.0 kPa | 31.0 kPa |
| 回転 | 720 rpm | 705 rpm |
| 燃料 | 1.11 L/h | 0.71 L/h |

**フラグが立っているとき MAP が低い例は 1%。** 逆(OFFなのに MAP 高い)が 18% あるのは、
ファンなど別の負荷か、クラッチが直前に切れた過渡とみられる。

燃料の差 +0.40 L/h (+56%) は、アイドル時のコンプレッサー負荷として妥当。
熱量に直すと 3.7 kW、熱効率25%として軸出力 0.9 kW。

**なお 0x1103 は bit2/bit3/bit4 を持つビットフィールド** (観測値 0/4/12/16/20/28)。
bit2 以外は未同定。0x1104 は 0/1 のみで純粋な1ビット。

### ヘッドライトは同じ手が使えなかった

夜間走行 (25,204秒) と昼間走行 (15,658秒) を比べたが、**電圧の差は +0.03V** しか
なく、どの PID も分離しなかった。

- オルタネータが電圧を厳密に制御するため、ヘッドライト程度 (約10A) では動かない
- 夜昼の比較は気温・交通・走り方が同時に変わるため交絡が大きい
  (実際に差が出たのは 001F 始動後経過時間、000F 吸気温 40℃/48℃ など、すべて説明がつく)

エアコンが成功したのは、**アイドル停車中という他が動かない状態で断続していた**ため。
ヘッドライトも同じ条件 (停車・アイドル・20秒ON/OFF) で試験する必要がある。

## 0x17B1 / 0x17C1 — シフトレンジ (2026-09-01 同定)

同じレンジを2通りの符号化で持つ。冗長系とみられる。

### 0x17B1 — ビットフィールド

| レンジ | b1 | ビット |
|---|---|---|
| R | 1 | bit0 |
| N | 2 | bit1 |
| L | 4 | bit2 |
| S | 8 | bit3 |
| D | 16 | bit4 |
| P | 32 | bit5 |

一致率 94〜99% (n=30,013)。

### 0x17C1 — コード値

| レンジ | b1 |
|---|---|
| L | 49 |
| S | 87 |
| D | 128 |
| R | 203 |
| P | 234 |

一致率 93〜100%。HOLD の有無では変わらない (D と D+HOLD がどちらも128、
S と S+HOLD がどちらも87)。**HOLD は 0x231 B1 bit7 にしか出ない。**

### 見つけ方

出発の瞬間に着目した。停車・アイドルのまま P→D とシフトするので、他が
動かない状態でレンジだけが変わる。

    00:48:56 (車速0)  17B1  32 → 16     P → D
    01:53:01 (1.8km/h) 17B1  16 → 1     D → R
    01:53:13 (車速0)   17B1   1 → 32    R → P

「出発時と駐車時で逆順になる」信号を探していて見つかった。狙いはヘッド
ライトだったが、そちらは見つからず、代わりにレンジが出た。

## 残り12個は相関では出ない

既知の全状態 (レンジ / ギア / HOLD / ロックアップ / ブレーキ / エアコン /
ファン / 速度 / 回転 / 負荷 / MAP / 水温 / ATF / 電圧 / 燃料レート) と
突き合わせたが、どれも一致率 90% に届かない。

    1782 17A0 097C 1410 16E8 16CD 17BB 17BC 096E 098E 16E9 1746

**098E と 16E9 は b1 が常に一定** で、変動は b2 側にある。b1 だけを見る
解析では捉えられない。次はバイト単位ではなくビット単位で当たること。

制御実験が要る。停車・アイドルのまま 20秒ON → 20秒OFF → 20秒ON を行う。

| 操作 | 狙い |
|---|---|
| ヘッドライト | 電気負荷。今回の夜昼比較では交絡が大きく出なかった |
| リアデフォッガー | 大電流負荷 |
| ブロワー 最弱↔最強 | 電気負荷の段階 |
| ステアリング据え切り | パワステ負荷 |
| N でアクセルを煽る | 負荷ゼロでの回転依存量 |
