# 車両調査スクリプト

エンジンをかけた状態で、順に実行する。所要時間の目安つき。

## 1. 標準PIDの対応確認 — 30秒・停車で可

```
sudo python3 /opt/pi-obd-meter/scripts/ops/probe-standard-pids.py
```

対応PIDビットマップ (0x00/0x20/0x40/0x60) を取り、対応している全PIDの
実値を読む。**2026-08-31 に実行済み。結果は下記。**

## 実行結果 (2026-08-31, ZJ-VE / DBA-DY3W)

**大気圧 0x33 は非対応だった。** あわせて外気温 0x46、エンジン油温 0x5C も非対応。
対応PIDビットマップから確定したので、これで決着とする。大気圧が要るなら
外部センサー (BME280) しかない。

| PID | | 結果 |
|---|---|---|
| 0x33 | 大気圧 | **非対応** |
| 0x46 | 外気温 | 非対応 |
| 0x5C | エンジン油温 | 非対応 |
| 0x43 | 絶対負荷 | **★対応** (アイドル 18.8%) |
| 0x3C | 触媒温度 | **★対応** (518℃) |

### 大気圧が非対応でも実害は無かった

当初「ハードコードした `atmosphericKPa = 101.3` のせいで、比叡山 (標高848m)
では体積効率を1割過大に見積もる」と書いていた。**これは誤りだった。**

`calcFuelEconomy` は MAF があればそちらを最優先で使う。実機の API を
確認すると `maf_airflow = 1.71 g/s` が入っており、燃料レートも

    1.71 × 3600 ÷ (14.7 × 750) = 0.5583  → ×1.12 = 0.6254 L/h

で `fuel_rate_lh = 0.62537...` と完全に一致した。**MAF 経路が使われており、
Speed-Density (MAP/大気圧) の分岐はこの車では通らない。**

MAF は空気の質量を直接測るので、標高による空気密度の低下は自動的に
織り込まれる。**大気圧の補正はもともと要らなかった。**

`atmosphericKPa` のハードコードは、MAF を持たない車で Speed-Density に
落ちたときだけ効く。この車では死にコードである。

### 新たに分かった対応PID

**0x43 絶対負荷** — SAE J1979 の Absolute Load Value。ECU 側で大気圧補正が
入った正規化値で、標高の影響を受けない。MAF を持たない車の燃料モデルには
MAP より適した入力になりうる。この車では MAF があるので優先度は低い。

**0x3C 触媒温度** — 実測 518℃。触媒の過熱は実在する故障モードなので、
健全性監視に使う余地がある。

### ついでに分かった車両の状態

- **MIL 消灯・DTC 0件** (0x01 の応答 `00 06 C0 00`)
- **短期燃料トリム -0.78%** — ほぼゼロ。混合気の補正がほとんど要っていない

## 2. ブレーキ信号の探索 — 15分・広い駐車場か交通のない道

```
sudo python3 /opt/pi-obd-meter/scripts/ops/capture-brake.py
```

画面の指示どおりに操作し、各操作の直前に Enter を押す。押した時刻が
ラベルになる。回収して Mac で解析する。

```
scp laurel@<pi>:/var/log/can-verify/brake_*.{log,labels} .
python3 scripts/ops/find-brake-bit.py brake_*.log brake_*.labels
```

**「ブレーキを踏まずにアクセルオフだけで減速する」手順を必ず含めること。**
これが対照群になる。無いと、単に減速と相関するだけのビットを誤って掴む。
手持ちの生ログで 0x200 を調べた際、相関が全部弱く (r=+0.20/-0.30/+0.08)
決着しなかったのは、走行データが最高17km/hの駐車場走行しか無かったため。

## 3. 勾配PIDの探索 — 登坂を含む走行が要る

poll22 が動いていれば追加操作は不要。**連続した登りを走ること**が条件。

```
scp laurel@<pi>:/var/log/can-verify/poll22_*.csv .
python3 scripts/ops/find-grade-pid.py poll22_*.csv
```

FN4A-EL は road load / grade logic で変速線を動かす。登坂で不要な
シフトアップを避け、降坂でエンジンブレーキを残すには、PCM が勾配相当の
量を持っていなければ制御できない。#150 の未同定 PID 17個のどれかである
可能性が高い。

**2026-08-31 時点の絞り込み結果 (平地データのみ、n=1,269,416):**

| PID | 変動幅 | 車速相関 | 判定 |
|---|---|---|---|
| **098E** | 0〜40 | +0.243 | ★停車中は常に0、走行中のみ動く |
| **1746** | 0〜5376 | +0.200 | ★停車中は固定、走行中に動く |

17個から2個に絞れた。**ただし平地のデータなので、これは「性質が合う」
までで同定ではない。** 登坂データで値が跳ねるかを見る必要がある。

断定するには GPS の標高 (#164) か IMU (#165) との照合が要る。
